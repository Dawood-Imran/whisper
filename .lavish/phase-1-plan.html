Phase 1 implementation plan

Prove the voice loop before building the daemon.

Phase 1 is a controlled prototype. We will build the smallest useful command-line flow that records audio, transcribes it locally, and gets text into the Codex CLI prompt.

Phase 1 outcome A user can run voice-codex-once, speak for a short fixed duration, and see the transcribed text copied or inserted into the focused terminal. The user still reviews the prompt and presses Enter manually.

What We Are Doing

Validate the machine

Detect session type, microphone devices, available command-line tools, and likely insertion backend.

Build the one-shot flow

Record one short audio clip, transcribe it locally with faster-whisper, then copy or insert the result.

Measure reliability

Capture timing and failure points so the later daemon is orchestration around proven behavior.

What We Are Not Doing Yet

No background daemon

Daemon lifecycle adds logs, state, process management, and startup behavior. That belongs after the core loop works.

No global hotkey

Global shortcuts create permission and conflict issues. Phase 1 can be triggered manually from the shell.

No silence detection

Silence detection adds tuning complexity. Fixed-duration recording gives us a stable first test.

Implementation Flow

The first implementation should follow this order so each step tells us something useful before the next one starts.

1

Project skeleton

Add pyproject.toml, package folder, and CLI entry points.

2

Preflight

Check Python, desktop session, microphone devices, and insertion tools.

3

Recorder

Record fixed-duration mono WAV at 16000 Hz.

4

Transcriber

Run local faster-whisper and return text plus elapsed time.

5

Inserter

Copy text to clipboard and attempt terminal paste where supported.

Files To Create In Phase 1

File Purpose Phase 1 Boundary
pyproject.toml Package metadata, dependencies, and console scripts. Keep dependency list focused on the one-shot prototype.
voice_codex/cli.py Expose preflight and once commands. No daemon command yet.
voice_codex/preflight.py Diagnose environment readiness. Report findings; do not mutate system configuration.
voice_codex/recorder.py Record fixed-duration audio to a temporary WAV file. No toggle or silence detection yet.
voice_codex/transcriber.py Load and run faster-whisper. Use default local CPU settings first.
voice_codex/inserter.py Clipboard and best-effort focused-window insertion. Clipboard fallback is acceptable on Wayland.

Acceptance Criteria

  • 1voice-codex-preflight reports session type, microphone availability, and insertion backend readiness.
  • 2voice-codex-once records a short clip without crashing.
  • 3Transcription runs locally and produces readable text.
  • 4The result is copied to the clipboard even if direct insertion fails.
  • 5On X11 with required tools, the result can be pasted into the active Codex CLI terminal.
  • 6The command does not press Enter or auto-submit to Codex.

Risks And Mitigations

Risk Why It Matters Phase 1 Mitigation
Wayland blocks insertion Many Wayland sessions restrict synthetic keyboard input. Always copy to clipboard; report clipboard-only mode clearly.
First transcription is slow CPU inference may feel too slow for interactive Codex usage. Measure elapsed time and start with base.en plus int8.
Microphone device mismatch Wrong default input device can produce silence or errors. Preflight lists devices and recorder uses the system default first.
Terminal paste shortcut differs Some terminals use Ctrl+Shift+V, others use Ctrl+V. Start with configurable X11 paste command and clipboard fallback.

First Implementation Slice

Start here

Create the Python skeleton and voice-codex-preflight. This gives us immediate facts about the current machine before installing or debugging model behavior.

Then build

Add voice-codex-once using reusable recorder, transcriber, and inserter modules. The later daemon should call the same modules rather than duplicate them.

Understanding Checklist

  • ✓Problem and root cause: the full product crosses several Linux integration boundaries, so Phase 1 isolates them.
  • ✓Relevant code path: CLI command to recorder, transcriber, inserter, and fallback reporting.
  • ✓Solution decision: one-shot command first, daemon later.
  • ✓Edge cases: Wayland, missing tools, bad microphone default, slow model, paste shortcut mismatch.
  • ✓Tests and verification: preflight output, recording smoke test, transcription smoke test, clipboard/insertion check.
  • ✓Broader impact: Phase 1 modules become the stable base for Phase 2 daemon work.
