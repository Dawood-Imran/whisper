Plan review

Voice-to-Codex should start as a one-shot proof, not a daemon.

The requirements plan is directionally strong. The main adjustment is sequencing: validate the fragile Linux integration points before adding hotkeys, systemd, silence detection, or richer vocabulary tooling.

First thing to do Build a tiny voice-codex-once prototype plus a preflight check. It should record a short clip, transcribe locally, copy the result, and attempt to paste into the focused Codex terminal.
  • WhyIt separates microphone, Whisper, clipboard, terminal paste, and desktop-session issues.
  • DefaultUse Ctrl+Alt+R later; avoid Ctrl+R until conflicts are tested.
  • ScopeNo daemon, no systemd, no Wayland polish, no silence detection in the first slice.

What Problem Exists

Too many moving parts

The full flow crosses audio capture, local ML inference, global hotkeys, clipboard/input injection, terminal behavior, and desktop permissions.

Linux session risk

X11 and Wayland behave differently. On Wayland, keyboard injection can fail or require ydotoold and /dev/uinput permissions.

Shortcut conflict

Ctrl+R is shell reverse search. A global listener may collide with normal terminal usage, so it should not be the first default.

Recommended First Milestone

Treat the first milestone as a technical spike with a crisp success condition: spoken text appears in the active Codex CLI prompt, and the user still presses Enter manually.

1

Preflight

Detect XDG_SESSION_TYPE, microphone devices, ffmpeg, clipboard tool, and paste backend.

2

Record

Capture a fixed 5-10 second WAV file through sounddevice.

3

Transcribe

Run faster-whisper locally with base.en, CPU, and int8.

4

Insert

Copy to clipboard and paste with xdotool on X11, fallback to clipboard-only.

5

Measure

Log latency, insertion success, and transcription quality before designing the daemon.

Phase Order I Would Use

Phase Build Success Condition Do Not Include Yet
0 Preflight command: session, mic, dependencies, insertion backend. We know whether this machine is X11, Wayland, or clipboard-only before implementation expands. Model loading, hotkeys, daemon.
1 voice-codex-once: fixed-duration record, transcribe, paste/copy. One spoken prompt lands in Codex CLI without manual copy/paste. Systemd, global shortcut, silence detection.
2 Vocabulary file and deterministic corrections. Names like Dawood, Codex, FastAPI, and JWT survive common mishearings. Fuzzy correction unless the deterministic map is insufficient.
3 Daemon with toggle hotkey and persistent model. Ctrl+Alt+R toggles recording and inserts text while Codex is focused. Auto-submit by default.
4 Wayland support, robust fallbacks, systemd install, CLI controls. User can start, stop, diagnose, and recover from insertion failure. GUI or broad desktop-environment perfection.

Key Design Decisions

Agree with faster-whisper first

It keeps the first implementation Python-native, local, and testable. Only revisit whisper.cpp if packaging or performance becomes the bottleneck.

Agree with manual Enter

Insertion without auto-submit protects the Codex workflow from bad transcripts, accidental recordings, and vocabulary correction mistakes.

Add preflight before daemon

The plan has implementation phases, but a phase-zero diagnostic will save time because Linux input injection is the highest uncertainty.

Delay fuzzy matching

Fuzzy matching can silently damage code terms. Start with exact corrections, then add conservative fuzzy rules only after observing real mistakes.

Implementation Shape

Recommended first PR

Create the Python package skeleton, config defaults, a preflight command, and voice-codex-once. Keep the code modular enough that recorder, transcriber, vocabulary, and inserter can be reused by the later daemon.

Module First Responsibility Reason It Matters
recorder.py Record fixed-duration mono WAV at 16 kHz. Confirms microphone and audio stack before adding toggle behavior.
transcriber.py Load faster-whisper and return plain text plus timing. Measures whether CPU inference feels usable on this machine.
inserter.py Clipboard + X11 paste, with clipboard-only fallback. Proves the Codex terminal can receive text without manual copy/paste.
cli.py Expose preflight, once, and later control commands. Keeps diagnostics user-accessible before daemon logs exist.

Understanding Checklist

  • ✓Problem and root cause: the risk is integration complexity, not the basic idea.
  • ✓Relevant flow: hotkey → record → transcribe → correct → insert into Codex CLI.
  • ✓Solution decision: first prove voice-codex-once, then daemonize after the flow works.
  • ✓Edge cases: Wayland restrictions, shell shortcut conflicts, slow first transcription, bad custom vocabulary corrections.
  • ✓Verification: success means a spoken prompt lands in the focused Codex CLI input, with manual Enter still required.
  • ✓Broader impact: this creates a reusable foundation for daemon, vocabulary, systemd, and silence detection later.

Bottom Line

Move forward, but narrow the first implementation. The first thing I would do is create a phase-zero diagnostic and a voice-codex-once command. Once that works on this machine, the daemon is mostly orchestration around proven modules instead of a large unknown system.
